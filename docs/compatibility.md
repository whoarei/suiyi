# 回填验证记录

## 主题配色

托盘提供十种配色，默认橙色；颜色偏好保存在 `HKCU\Software\Suiyi\ThemeColor`。浅色和深色读取 Windows 的应用模式，通过系统偏好变更通知同步更新，打开托盘菜单时也会刷新系统状态。浮窗、设置、更新窗口、模型输入和下拉、快速模式提示及托盘菜单共享主题颜色。

新增 8 项集成检查使用隔离注册表分支与隐藏的真实设置控件，覆盖默认橙色、十色菜单勾选、菜单切换与持久化、编辑内容和选区保留、系统深浅变化、模型编辑器配色、二十组配色的主文字及按钮对比度、损坏偏好回退和系统模式读取。未修改真实系统主题。

## 安装包与程序内更新

新增 Inno Setup 安装包，当前用户安装到 `%LOCALAPPDATA%\Programs\Suiyi`，不要求管理员权限。更新窗口识别官方安装附件及摘要，下载时限制大小、HTTPS 重定向主机和次数，校验 SHA-256 后启动安装器；安装器通过命名事件正常关闭随译并覆盖升级。用户配置和密钥存储位置不变。

新增 15 项下载检查使用 HTTP 替身和虚构文件，覆盖安装附件、元数据、官方 CDN、重定向边界、摘要、截断、超长、取消、网络、超时及清理范围。安装器隔离实测另覆盖首次安装、关闭持锁夹具后的升级、卸载及配置保留。

## 检查更新

托盘菜单增加“检查更新”，以独立匿名请求读取 GitHub 的最新正式 Release，按语义版本比较本机程序的构建版本。有新版时打开固定仓库下对应标签的发布页面；本机较新时不会提示降级。查询仅由用户主动触发，关闭窗口取消在途请求，失败后允许手动重试。

更新逻辑新增 20 项自动检查，覆盖数字及预发布排序、忽略构建摘要、正式版筛选、固定官方链接、认证隔离、无正式版、限流、服务失败、网络异常、坏 JSON、声明及未声明大小上限、取消、超时及流错误。使用 HTTP 替身，不访问网络。

Windows 11 本机联调：从构建版本读取到 `0.1.4-dev`，真实匿名查询返回正式版 `v0.1.3`，检查窗口正确显示“当前版本较新”及最新正式版本号。

## 密钥显示与隐藏

设置中的 API Key 输入框增加小眼睛，允许显式查看当前输入或当前地址已保存的密钥。明文和遮蔽输入保持同步；隐藏、设置失焦和关闭时清空明文控件。已保存密钥即使在显示期间被编辑，切换地址时也会清空，避免把它作为替换值传给另一个地址。

新增 9 项检查使用真实的设置窗口控件但不显示窗口，数据来自临时测试目录与虚构 Key，验证默认隐藏、读取当前地址、切换隐藏、编辑同步、失焦隐藏、新输入显示、地址变化清空、新地址自己的密钥及关闭清空；未读取或显示生产密钥。

## 托盘菜单外观

菜单继续使用 ContextMenuStrip 承接原有操作与系统交互，自定义绘制圆角、主题色选中状态、线条图标和分组线；快速模式与开机启动使用滑动开关表示 Checked 状态。菜单按显示器 DPI 缩放尺寸和图形，并自动跟随系统深浅。

本机通过相同菜单实例的诊断预览验证了设置入口，以及快速模式关闭和开启时的显示与实际操作；验证后恢复原来的开启状态。开机启动状态正确显示，未为样式测试修改真实启动选择。诊断用的浮窗右键预览入口不包含在正式版本中。

## 通用接口与极简设置

2026 年 11 月 14 日，移除厂商与模型预设，改为 API 根地址、Key 和可编辑模型 ID。已有版本 1 的本机 DeepSeek 地址、模型与加密密钥成功加载，设置页没有要求重新输入 Key；点击获取后，真实接口返回两个模型 ID，作为下拉选项显示。点击测试后，单行和包含空行的多行翻译均通过。保存后迁移为版本 2 和按地址分别加密保存的密钥文件。

通用请求仅使用 model、messages、stream，不依赖厂商私有的思考控制、温度或 JSON 输出参数。通过提示词要求多行 JSON，再验证行数和空行；模型默认生成策略由接口决定。不同接口的路径、模型命名、匿名本地调用、模型分页、404/405/501 手填提示、认证失败、响应上限、循环游标、取消及超时由模拟 HTTP 检查覆盖。本次真实服务联调仍使用用户原先保存的接口，没有实际验证每一家厂商。

设置页从 456 像素宽的卡片布局缩减为 392×323：四行输入、快速模式、测试和保存。关闭使用右上角 × 或 Esc；快捷键改为点击输入框后直接录入，已实际验证 Ctrl+Alt+Y 和当前 Ctrl+Alt+T 都能录入。模型获取使用下载图标，悬停显示“获取模型”；不显示厂商选项或固定模型清单。[当前界面](assets/settings-minimal.jpg)

图标按钮在迁移后的配置上再次取回模型列表；手动填写未列出的 `manual/model:latest` 后关闭设置，未保存修改被丢弃。随后在 WPF 测试输入框选中“这条消息会自动翻译。”并按 Ctrl+Alt+T，实际替换为“This message will be translated automatically.”，过程中没有显示翻译浮窗，说明通用请求和迁移后的密钥也适用于快速模式。

## 快速模式、设置页与自定义快捷键

当时设置页使用翻译服务与快捷键两块卡片，提供右上角 ×、底部“关闭”、Esc、恢复默认和快速模式开关；现已由上方极简布局替代。从隐藏托盘状态打开设置时不显示空白翻译浮窗。[历史界面](assets/settings-ui.jpg)

快速模式无选区或失败时只显示约 3 秒的非激活、可穿透提示，不打开翻译浮窗；成功时不显示提示。取消、翻译失败、空结果、迟到响应、窗口切换、选区变化、部分提交和剪贴板竞争由自动检查覆盖。网络失败提示的具体错误分类继续复用 DeepSeek 协议检查，未为 UI 冒烟测试修改真实 API Key 或断开用户网络。

## 当前限制

当前微信自绘界面对自动化接口主要暴露顶层窗口；原生焦点句柄也指向聊天主窗口。M0 可以恢复该窗口及其保留的输入焦点，但无法自动证明焦点一定处于聊天正文输入框，也无法从句柄区分同一窗口中的搜索框或会话。

因此，必须先在准备回填的输入框中放好光标，再主动按快捷键。离开浮窗时清除绑定；每次回填消耗一个目标会话。对只暴露整个窗口的自绘控件，当前版本仍只能确认窗口与原生焦点，不能自动证明具体输入字段。此次通用版本未重复微信实测，上文微信结果为此前版本记录。

M0 曾只允许微信、记事本和项目测试编辑器作为回填进程；当前版本已移除此开发白名单。进程名称映射仅用于显示，不把“没有限制应用”当作“所有控件都可靠可用”。辅助识别失败或自绘控件缺少元数据时，可能保留原生焦点回填并提示用户确认，不能保证识别所有自绘密码或只读字段；无法取得焦点线索时只开放复制。

以下项目尚待进一步验证：浏览器与更多外部编辑器的选区替换、密码与只读自绘控件、更多中文输入法及译文编辑时的组合输入、多屏混合 DPI、休眠恢复、高权限目标、剪贴板与焦点的极短时间竞争，以及兼容性方案中的连续 30 次回归。快速模式提示目前显示在主屏幕工作区右下角。

## 自动检查

核心逻辑 36 项：回填状态、异步验证期间会话失效或取消、未知应用名、控件身份变化、密码、只读、不可用/非输入、错误窗口及不透明控件元数据检查；选区变化停止粘贴并保留译文、文字或位置变化影响选区摘要，以及 2000/2001 长度边界不截断替换。新增 11 项快速模式检查，覆盖直接替换、无选区、未配置、失败、空结果、取消后迟到响应、切换窗口不抢焦点、选区变化、部分提交、异常脱敏与剪贴板竞争；另有 3 项快捷键有效性及显示检查。
