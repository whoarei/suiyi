# 回填验证记录

## 通用输入框扩展

2026 年 11 月 14 日，同一 Windows 11 x64 环境，移除原来的进程白名单后进行了以下真实 UI 验证。使用同一次 DeepSeek 实际返回的英语译文，分别从目标控件按 Ctrl+Alt+T，再在浮窗按 Ctrl+Enter；通过目标控件里的实际内容确认结果。

| 验证 | 结果 |
| --- | --- |
| WPF 普通多行 TextBox | 返回原控件并插入完整译文，字符计数为 66 |
| Edge 网页 textarea | 识别为可编辑控件，完整译文出现在原多行输入框 |
| Edge 网页 contenteditable | 完整译文出现在富文本区域，前一个 textarea 保持原内容 |
| WPF 只读 TextBox | 进入复制模式，回填按钮禁用 |
| Edge 网页 readonly input | 进入复制模式，回填按钮禁用，原文字保持不变 |
| Edge 空 password input | 仅验证元数据识别，未填写任何密码；回填按钮禁用 |

浏览器页面为项目自带的 `tools/browser-input-target.html`，没有提交或网络功能。截图保存在 `artifacts/browser-input-verification.jpg`。没有把工具日志的 Submitted 状态当作写入成功依据。

现采用原生 Edit/RichEdit 状态检查，以及独立辅助进程中的只读 UI Automation。对可确认的编辑控件，捕获其运行时身份，回填前再次核对；遇到已识别的密码、只读、禁用或非输入控件直接停止。UIA 每次上限 900 毫秒，超时终止子进程，避免第三方提供程序卡住主界面。辅助进程不读取名称、输入值和正文，也不加载翻译设置。

以上是功能冒烟验证，尚未完成连续 30 次回归，不代表所有桌面软件或浏览器页面已兼容。Win32 原生编辑框的密码/只读样式另用真实控件进行自动检查，未进行完整外部窗口回填实测。

## DeepSeek 翻译联调

2026 年 11 月 14 日，在同一台 Windows 11 x64、微信 4.2.0.13 环境完成真实 DeepSeek API 联调。密钥由用户直接在本机设置窗口填写，使用 `deepseek-flash`，没有将密钥放入聊天、源码或运行包。

| 验证 | 结果 |
| --- | --- |
| 单行中文自动翻译 | 输入会议时间示例后，返回包含次日下午三点及参会询问的英语译文 |
| 原文变化 | 新请求进行中，旧译文不可编辑、复制或回填 |
| 多行中文与符号 | 真实返回的两行英语保持换行，保留 ☕；行数或空行不符时拒绝输出 |
| 原文中文组合输入 | 出现拼音候选时状态为正在选词，复制与回填禁用；Esc 取消候选后可继续输入 |
| 选词期间 Enter | 结束当前输入法组合，没有触发回填 |
| 手动润色译文 | 修改为两行英语后显示已手动修改，收起重开时保持修改 |
| 实际微信回填 | 微信文件传输助手草稿中出现手动润色后的两行英语；没有用中文原文替代译文 |
| 密钥跨重启 | 重启程序后自动加载加密密钥与模型，仍可进行真实翻译 |
| 消息发送 | 测试期间未点击发送，文字仍留在草稿框 |

真实返回与手动润色分别验证。最初发现模型自行合并断行，现已改为多行 JSON 行数组并校验后重建换行；没有用本地预设译文替代真实接口结果。

译文编辑区也加入组合输入保护，但尚未完成各输入法、各按键组合的完整实机矩阵。完整兼容性与连续 30 次回归仍属后续工作。

## 当前限制

当前微信自绘界面对自动化接口主要暴露顶层窗口；原生焦点句柄也指向聊天主窗口。M0 可以恢复该窗口及其保留的输入焦点，但无法自动证明焦点一定处于聊天正文输入框，也无法从句柄区分同一窗口中的搜索框或会话。

因此，必须先在准备回填的输入框中放好光标，再主动按快捷键。离开浮窗时清除绑定；每次回填消耗一个目标会话。对只暴露整个窗口的自绘控件，当前版本仍只能确认窗口与原生焦点，不能自动证明具体输入字段。此次通用版本未重复微信实测，上文微信结果为此前版本记录。

M0 曾只允许微信、记事本和项目测试编辑器作为回填进程；当前版本已移除此开发白名单。进程名称映射仅用于显示，不把“没有限制应用”当作“所有控件都可靠可用”。辅助识别失败或自绘控件缺少元数据时，可能保留原生焦点回填并提示用户确认，不能保证识别所有自绘密码或只读字段；无法取得焦点线索时只开放复制。

以下项目尚待进一步验证：选区替换、密码与只读自绘控件、更多中文输入法及译文编辑时的组合输入、多屏混合 DPI、休眠恢复、高权限目标、剪贴板与焦点的极短时间竞争，以及兼容性方案中的连续 30 次回归。

## 自动检查

核心逻辑 18 项：原 10 项回填状态检查，增加异步验证期间会话失效、未知应用名、控件身份变化、密码、只读、不可用/非输入、错误窗口及不透明控件元数据检查。

原生结构 7 项：x64 输入结构大小与对齐、GUI 线程结构大小、事件数、事件类型、无 Enter，以及完整 Ctrl+V 的按下和释放顺序。这些检查不向桌面注入输入。

原生编辑控件 3 项：创建真实 Win32 单行、密码和只读控件，读取实际样式并检查回填判定；自动横滚不会误判为密码。这些检查不访问用户窗口。

翻译协议和调度 33 项：HTTP 请求参数、思考关闭、最终输出解析、结构化多行、错误归类与脱敏、响应大小、超时与取消、旧响应失效、缓存、组合输入、手动编辑、配置变化及限流等待。

本机设置 7 项：DPAPI 往返、配置字符串脱敏、密文保存、JSON 无密钥、保留已有密钥、损坏密钥恢复及配置损坏后的独立读取。这些检查使用临时测试目录与虚构密钥，不读取生产凭据。

开机启动 12 项：默认开启、关闭仅删除本程序项、关闭后的持久化、重新开启、移动后更新路径、关闭时移动不重启用、损坏偏好、中文与空格路径、命令限制、不重复改写、注册失败和偏好失败回滚。使用新建的独立 GUID 注册表分支及故障替身，不读取或改动真实登录启动项。

合计 80 项。真实登录后的启动行为仍需实际注销或重启验证；自动检查不注销用户会话。
